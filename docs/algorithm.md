# 盤面生成と軽量化

生成方式は Astra（`gpt-6-astra`、reasoning effort `xhigh`）の助言を受けて実装しました。

## 難易度の保証

移動可能な全状態を、車両ごとの可動方向の座標だけで表します。各座標を4ビットに格納するため、32台までの盤面を128ビットのキーで扱えます。

ランダムな車両配置から到達可能な状態を列挙します。20,000状態を超える成分は採用しません。列挙が完了した成分で、出口まで障害物のない全状態を始点に幅優先探索を行います。出口への最後の移動を含めた距離から、指定難易度の状態を選びます。一度に複数マス動かす操作も1手です。

すべての完成盤面について、得られた解を公開ルールの `GameSession.TryMove` で再生し、合法な移動だけでクリアできることを検証します。

## 8×8以上

横幅を `floor(N/2)`、高さを `N` とする論理盤面を作ります。

- 横向き車両は、表示盤面でX座標と幅を2倍にします。論理幅1は2×1、論理幅2は4×1になります。
- 縦向き車両は各論理列の右側に置きます。高さ2の車両は幅2のショベルカー、高さ3/4は幅1のトラック／トレーラーにします。
- 赤い車は2×1です。すべての大型盤面に2×2と4×1の車両が存在します。

表示盤面の解を `floor(X/2)` で射影すると、同じ手数以下の合法な論理盤面の解になります。逆に論理盤面の解は横移動量を2倍にすれば表示盤面に持ち上げられます。両方向の対応により、生成時の最短手数は等しくなります。奇数サイズの右端1列もこの関係を崩しません。

ユーザーは1マス刻みで自由に動かせます。ヒントでは、横向き車両の奇数X座標を左から順に偶数位置へそろえ、小さい論理盤面を解きます。この調整が入るヒント経路は現在位置からの最短を保証しませんが、全手を再生検証したクリア経路です。初期盤面の「最短」表示は厳密です。

## 待ち時間とシード再現性

ランダム探索の上限は経過時間ではなく探索した状態数で決めます。400,000状態を処理した場合や配置試行の上限に達した場合、同梱した検証済み成分を改めて探索し、シードからその難易度の状態を選び直します。難易度を下げたり、解けない盤面を返したりしません。CPU速度によって同じシードの結果が変わらない構成です。

## 検証

`dotnet run --project tests/RushHour.Tests -c Release -- --sweep` は7サイズ×4難易度×5シードを検証します。解の再生、難易度範囲、大型車両、奇数位置からのヒント、独立した物理盤面探索との最短手数比較を含みます。

`scripts/smoke.cjs` と `scripts/layout-smoke.cjs` は、WebView2の開発用CDPポート経由で実際のWindowsアプリを操作します。公開版はCDPポートを開きません。
